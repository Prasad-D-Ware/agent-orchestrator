AO Mobile — one drawer instead of four tabs

Today the app spends its whole bottom edge on Agents · Orchestrator · PRs · Settings, and three of those four are places you visit rarely. This concept moves navigation into a left drawer (Claude-iOS style), frees the bottom edge for the two things you actually do — find a session and start one — and gives desktop-parity chat actions a home in a ••• sheet instead of the composer row.

All chrome below is stock-iOS shaped: 44pt targets, grabber sheets, hairline separators, SF text, blurred floating dock. Everything maps to something that already exists in packages/mobile.

Sections 03–07 then walk the flows — pairing a Mac, starting a session from the phone, being found by an approval, reviewing and shipping the work, and reaching into the machine — informed by what T3 Code and Codex in ChatGPT ship today and by what AO’s desktop can already do that neither of them can.

4 tabs → 1 drawer Bottom edge = search + compose Settings = sheet, not a tab Chat parity = ••• sheet Projects = first-class Approve from the lock screen Reviewer agents → send to worker Merge from the phone

01 — The shell

The drawer is the whole nav surface. It holds destinations at the top (few, stable), live sessions as “Recents” underneath (many, changing), and identity + settings pinned to the bottom — so the thing you tap least is furthest from the thumb, and the session you tap most is one swipe from anywhere.

What this actually changes

Navigation

  • Drawer replaces the tab bar. Edge-swipe from anywhere; the burger button is duplicated in the dock so it’s thumb-reachable.
  • Settings loses its tab and becomes a sheet off the avatar row.
  • PRs loses its tab — it lives in the drawer with a count, and in the ••• sheet when it’s about the session you’re in.
  • Projects gains a screen it never had on mobile.

Bottom edge is the most valuable real estate on a phone. Spending it on four rarely-switched destinations was the tax.

Staying native on iOS

  • Sheets are real detent sheets (grabber, drag-to-dismiss) — matches the existing app/sheets/* routes.
  • Grouped-inset lists, hairline separators, 44pt targets, SF Symbols-shaped glyphs.
  • Search lifts into the nav bar like UISearchController, it does not become a modal page.
  • Dock is a blurred material bar, so content scrolls visibly under it.
  • Drawer is a gesture-driven pan, not a page push — the underlying screen stays alive.

Composer vs ••• split

  • Composer: +, model, approvals, mic, send, steer/queue. Everything that changes this message.
  • ••• sheet: shell, preview, PR, map, turn settings, rate limits, compact, rename, reload MCP, stop. Everything that changes this session.
  • Skills (/) and files (@) stay as inline triggers and live under +, so both muscle memories work.

Today’s composer row carries 6 icons plus a model label; four of them are session-level, which is why it reads as a toolbar rather than a text field.

What the references do — and don’t

  • T3 Code pitches “pretty much the full power of the desktop app”: multi-provider agent runs, file browsing, git actions, diff review, terminal. Pairing by code or managed connect. Its shape is desktop, shrunk.
  • Codex in ChatGPT pitches the opposite — stay in the loop from anywhere. QR pairing off the Mac, live streams of screenshots / terminal / diffs / test results, lock-screen approval cards, model switching mid-task, dispatch new threads. Reviewers note its diff view struggles past ~80 lines.
  • Neither has reviewer agents. AO’s review loop — a second agent comments, you resolve or send the finding back to the worker — has no equivalent in either app, and it is the most phone-shaped thing AO owns.

So: take Codex’s ambient posture (notify, approve, glance) as the spine, borrow T3’s reach-into-the-machine screens as secondary, and lead with the review loop.

Open questions

  • Does Terminal deserve a drawer slot, or is it only ever reached from a session?
  • Should Recents in the drawer be live sessions or recently opened — they diverge fast.
  • Android: drawer maps cleanly to a nav drawer, but the dock needs to clear gesture-nav insets (already handled in the current tab bar).
  • Merge from a phone — right call, or one tap too far from the code?
  • Live Activity per environment or per session? Per-session is more useful and much noisier.
  • Does “send to worker” need a confirmation, given it silently starts a turn on a machine you can’t see?

Polish still owed

  • Real agent logos (harnessLogoAssets) instead of the two-letter tiles.
  • Light mode — the app has a theme sheet; this whole concept is dark-only so far.
  • Motion: drawer pan, sheet detents, the streaming-token cadence in chat. None of it is expressible here and all of it decides whether this reads native.
  • Empty and error states for every screen above (offline, machine asleep, agent crashed, tunnel dropped).
  • Dynamic Type and the 44pt audit at the largest accessibility sizes.
